# 实时拖动定位与对比刷新（2026-10-16）

## 行为

主窗口和迷你窗口的共享进度条，现在会在拖动过程中向当前 libmpv 播放会话发送定位，主画面由播放器实际解码更新，不以缩略图覆盖视频。

- 首次拖动暂时暂停播放并记录原先的播放意图，避免拖动时连续播放音频片段。
- 移动时使用 `absolute+keyframes`，优先响应位置变化；实际画面可能是目标附近的关键帧。长 GOP 中多个相邻位置仍可能对应同一帧。
- 松手发送一次 `absolute+exact`，继续使用 pending seek / request ID 保持目标指针，随后恢复拖动前的播放/暂停状态。
- 点击快速释放时，尚未执行的预览请求会被最终定位替代。
- 换文件、显式导航、视图移除与关闭会清理拖动状态和定时器，按适用的当前文件恢复暂停状态；新文件不应继承拖动的临时暂停。
- 预览气泡功能独立于主画面的拖动定位，仍可关闭；图片实际时间按用户偏好继续隐藏。

## 调度与对比优化

- 原生客户端队列保存最新拖动目标及最新分隔线比例。过时的待执行更新通过 generation 丢弃。
- 交互调度约 120 ms 一次，实际派发也有最小间隔限制；这只是请求频率上限，不代表实测显示 FPS。
- 发出拖动定位后优先等待 mpv 的 `PLAYBACK_RESTART`；旧定位过慢时，最多等待约 800 ms 后允许新目标取代它。已有 GPU 工作仍不能被立即中止。
- 暂停对比不再由 SwiftUI 每次变化直接发送精确定位。原生调度合并分隔线更新，等待已有定位，再读取真实当前位置进行一次刷新；拖动结束后的最后比例不会因简单节流而遗漏。
- 对比比例已一致时不重复发送滤镜命令与定位。正常播放时只更新比例，不额外 seek。
- 对比更新和进度条拖动共用调度，拖动期间不会再额外发起对比刷新定位。
- 新增实际派发计数 `iive-scrub-seeks` 到现有 metrics 快照。

暂停对比当前仍需重新定位来跑滤镜，并非缓存已解码帧的纯重渲染。RIFE/SR 很重或片源定位困难时，画面更新仍可能慢；本轮没有给出加速百分比或实时帧率承诺。

## 基础验证

- Xcode arm64 Debug 构建通过，包含 Swift 调用与 Objective-C 新接口编译。
- `TimelineSeekSmoke` 通过：旧时钟、请求排序、完成/失败/超时、暂停短定位、换片及边界状态。
- `git diff --check` 通过。
- 未运行 GUI、真实视频拖动测试、模型性能测试或完整测试集。播放状态恢复、拖动观感和暂停对比尾次刷新由用户检查。
- 开发版：`build/PersonalTeam/IIVE Player.app`，仍依赖当前工作区和 Homebrew。
- 记录：`benchmarks/results/live-scrubbing-build-20261016.log`、`live-scrubbing-seek-smoke-20261016.txt`。

后续优先在用户反馈基础上调整交互频率；若重定位仍是主要瓶颈，研究暂停对比的缓存帧重渲染。模型优化继续以端到端耗时/P95及实际 CPU 回退次数为依据。
