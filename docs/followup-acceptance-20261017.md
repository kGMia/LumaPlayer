# 三项跟进验收与完善（2026-10-17）

## 验收结论

在途封面合并、文件指纹、VFR 平滑预算和迟滞逻辑已落盘。Uniform4f 在固定 mpv 源码与 prepare-mpv 脚本中均已注册。EDR 新增定时 drain 有效补齐了一个缺口，但原回退仍是“异步请求改色彩后立即画普通 FBO”，尚不是完整同步切换。本轮进一步修正；开关保持实验性质、默认关闭，不把编译或共享表面检查当作 HDR 画质验收。

## 本轮完善

### EDR / 色彩切换

- 新增渲染暂停门控。先等待渲染队列停止旧呈现器，清除/应用 ICC render 参数，再在 mpv 客户端队列批量设置输出色彩；两侧都确认成功后才恢复渲染。取消的旧任务不能释放新任务的门控。
- 异常回退立即阻止当前调用画到普通 FBO，随后恢复自动输出/所选 ICC。EDR 配置失败自动关闭实验选项；普通输出配置本身失败则明确显示渲染暂停，避免用未知色彩配置继续显示。
- live resize 不再因为尺寸变化临时使用普通 FBO；仍在 EDR 路径重建表面。此处重建有 drain 开销，尚不能宣称无卡顿。
- 进入 EDR 时清除已有 ICC，退出后恢复；使用屏幕**当前** headroom，而非把 potential headroom 当作可用亮度。迷你/全屏窗口迁移也重新应用配置。
- swap 与计数改由 drawable 实际呈现回调推进，不再在 GL 仅写入离屏表面时冒充已经呈现。待完成 Metal 命令也计入 pending，最后一帧错误可被检查；槽位释放后重新触发此前被推迟的画面。
- 缺少 compute write 支持时明确失败，不能用跳过软拐点的 blit 静默替代。允许 `MTLTextureUsageUnknown` 的通用纹理用法。
- 异步图层挂载带 generation 校验；主线程不再直接访问渲染队列持有的 bridge 来迁移窗口。

仍待验证：mpv linear 输出与 SDR white 的数值对应、是否重复 tone map、上下方向、不同屏幕真实亮度/色彩、字幕/截图一致性。当前软拐点逐通道处理也可能改变高光色相。CAMetalLayer 获取 drawable 和尺寸重建仍可能等待；不能称为整条链路完全非阻塞。没有实测端到端 HDR 性能或杜比视界画面。

### 音频封面

- 合并键按实际是否执行附加图片提取归一化，MP3/FLAC 等队列请求与主播放请求即使 embedded hint 不同，也可共享同一解码。
- 共享任务自行完成缓存写入；取消首个订阅者不会阻断其他订阅者或缓存。所有等待者均检查取消状态；取消不会杀掉其他订阅者仍依赖的解码，等待结束后返回 nil。
- 解码完成及返回等待者前再次核对文件指纹；文件在解码中发生变化时拒绝旧图片，旧任务不能用旧内容覆盖新缓存。
- 指纹包含同目录 cover/folder/front JPG/PNG，创建、删除或修改这些封面也会失效。仍依赖 mtime/size，不是内容哈希。
- 移除播放快照中主线程的同步文件 stat，后台最多每两秒复查当前封面；相同缓存图片不重复发布或刷新 Now Playing。64 项/64 MiB 是缓存像素预算，不包括在途解码和视图额外持有的图片。

### VFR / 预取

- 保留按有效 PTS 间隔平滑的帧对预算、倍速换算与迟滞；无效间隔清除旧平滑值，seek/reset 仍清除预算和样本。
- 至少 8 个有效耗时样本后才用 P95 调整预取，减少冷启动少量样本造成的变化；高分辨率约束仍有效。
- 当前滤镜会把超过 0.1 秒的相邻间隔当作不连续并重建，因此预算 helper 的 0.5 秒范围不能理解为滤镜已支持所有低帧率 VFR 插帧。

## 下一步指导

1. 用户先验收 EDR 开/关、暂停后拖动、全屏/迷你往返、不同屏幕移动；关注发灰/过暗、方向错误、旧帧不更新。普通 SDR/ICC 路径作为对照。出现异常先关闭实验选项，并记录片源、显示器和触发步骤。
2. 开发优先补齐 EDR 数值色彩验证与 drawable 遮挡/超时处理，再考虑默认启用。采用固定角标、灰阶和超白色块验证完整 mpv→屏幕链路，避免仅验证 IOSurface。
3. 封面下一步加入内存压力清理及在途解码并发上限；管线再以相同素材对比预取 1/2/4 的 P95、峰值内存和掉帧，决定最终策略。现阶段不建议继续叠加新模型来掩盖调度或显示瓶颈。
