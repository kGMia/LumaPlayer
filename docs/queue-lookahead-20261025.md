# 媒体时间预取窗口 · 2026-10-25

RIFE 与 Apple/FSRCNNX 原生滤镜的自动预取现在同时考虑帧数、内存和媒体时间：根据已交给下游的帧 PTS、后续队列 PTS、输出节奏、播放倍速与处理 P95，限制启动下一批推理的时机。预取窗口为处理提前量加一帧，最多两个输出间隔、50 ms。它是每级滤镜的入队条件，不是显示器截止时间或端到端延迟保证；一次必要推理产生的批次可以超过窗口。

只延后新任务，不丢帧、不改写 PTS。空队列始终能够继续；缺失/异常时间戳采用保守帧数限制。Seek 重置节奏及诊断状态，沿用 generation 机制丢弃过期任务结果。暂停期间不使用墙钟停留时间作超时依据。固定 `prefetch=1/2/4` 保留为对照模式，仍受原有内存限制。

新增诊断字段：`queue_ahead_ms`、`queue_budget_ms`、`time_prefetch_blocked`、`time_prefetch_deferrals`。未知时间不填零；profile 汇总保留这些字段。阻止预取次数不是掉帧数。

基础验证：

- C 定向检查通过：窗口边界、VFR、倍速、时间戳异常、Seek 状态重置、大批次排空与内存限制。
- libmpv 增量构建通过。
- 半秒无窗口 RIFE→FSRCNNX 检查通过：30 帧有序输出、确认插帧及 512×256 超分、正常 EOF。
- Debug 应用构建、打包及现有个人签名校验通过；交付 `build/IIVE-Player.app`，内置已更新的 libmpv。未启动应用，未做完整测试或持续性能测量。

实际拖动响应、连续播放及不同视频下的收益交给用户验证。下一步以诊断中的队列时间、掉帧和 Ready 等待为依据调节窗口；不要仅因模型吞吐提高就增加预取深度。
