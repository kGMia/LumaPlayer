# Native pipeline update — 2026-10-24

- RIFE / FSRCNNX now publish `gpu_span_ms` and `cpu_wait_ms` to filter metadata, optional per-job traces and the Performance inspector. The GPU span runs from the first command's start to the final root command's end, covering all timesteps and MPS internal splits, including scheduling gaps. CPU wait measures only the existing final blocking wait. They overlap and must not be added; neither is GPU utilization or display latency. No additional command buffers, GPU barriers or completion callbacks were introduced for these metrics.
- Cache reuse, rebase, scene-cut holds, failed/bypassed jobs and unavailable timestamps do not claim inference timings. Metadata omits unavailable fields, traces use `null`, UI shows N/A. Seek/reset clears the snapshot. Apple VideoToolbox model timings remain N/A because that API does not expose this GPU interval.
- The pinned mpv auto-deinterlacer now selects FFmpeg `yadif_videotoolbox` for NV12/P010 VideoToolbox frames with a hardware frames context. Other inputs retain CPU BWDIF; missing filter / Metal initialization failure uses the existing CPU fallback. This is YADIF, not neural interpolation, and it still has GPU synchronization inside FFmpeg. The existing AI-FI bypass for deinterlace Auto/On remains. On/Auto and parity changes drain/rebuild the child filter; hardware subformat changes also rebuild it.

Validation: Release native libraries + mpv and Debug player built; ten telemetry-parser checks, native C timing ABI/unavailable-data check and a 0.5-second synthetic software-deinterlace headless playback passed. Packaging verifies relocated dependencies and signatures. No GUI, hardware-deinterlace visual verification or model performance benchmark was run; no speedup is claimed. Logs are `benchmarks/results/metal-pipeline-*20261024.log` and `deinterlace-software-smoke-20261024.log`.

Reference inspected: [FFmpeg Metal YADIF implementation](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_yadif_videotoolbox.m), bundled filter option listing, pinned mpv `filters/f_lavfi.c` and `filters/f_auto_filters.c`, Xcode SDK `MPSCommandBuffer.h`. The built mpv patch is reproducible through `scripts/prepare-mpv.py`; no FFmpeg implementation is copied into our tree.
