# Agent 改动简要验收（2026-10-17）

结论：保留签名采样、动态预取、SR 缓存限制与共享音频封面的方向。EDR 桥接代码可以继续作为原型，但新增播放器挂载存在正确性问题，本轮暂时关闭入口，没有将其作为可用 HDR 输出交付。

## 已修复

- RIFE 预取原来使用 `fps >= 60 ? 24 : 24`，导致所有源片都按 24fps 计算预算。改为输入帧的 nominal_fps 与实际播放速度，未知帧率不套用延迟阈值；worker 忙时不再为每个输出重复排序 P95 窗口。这里使用名义源帧率，尚非 VFR 的局部 PTS 预算。
- 预取阈值只是“何时启动下一任务”的条件，并非总队列长度上限。ready 与 worker batch 的既有容量约束不变，不能把阈值 1 宣称为只持有一张 IOSurface。
- 音频缓存增加 **64 MiB 解码像素预算**，同时保留最多 64 项限制；同步索引随淘汰清理。这是缓存自身预算，正在显示的图片、队列持有图片以及解码中的资源另计。
- FFmpeg 封面回退改为只选择 `attached_pic` 流；不再因为文件扩展名像音频就允许把任意视频首帧当作封面。
- EDR 着色器编译失败现在明确返回错误，不能在初始化阶段静默当作成功。
- EDR 应用开关显示不可用，环境变量和已保存偏好无法绕过限制；应用继续使用现有 OpenGL/ICC 路径，避免将线性光输出送入普通 FBO。原型与挂载代码保留，未删除研究成果。

## EDR 暂不验收的原因

1. `presentReadyFrame` 只在新帧且成功取得写入槽后调用。暂停画面的 GL fence 尚未完成时没有独立推进；两个槽都待呈现时又可能无法取得写入槽，形成停滞。
2. 没有呈现成功就立即渲染默认 FBO，但此前异步设置的 `target-trc=linear` 等配置没有随失败或 live resize 恢复，Metal 图层也可能仍覆盖旧帧。这不是可靠的无感回退。
3. 切入 EDR 没有先清除已配置的 ICC render 参数；源峰值字段被保存但没有参与着色器曝光计算，`exposureScale` 恒为 1。源亮度、SDR white 与 mpv 输出映射仍需建立一致约定。
4. ShaderWrite 不可用时退到 blit 会绕过软拐点；提交 command buffer 后即报告 swap 也不能证明已呈现。需要实际呈现完成回报和错误传播。

这些问题涉及呈现状态机与色彩配置，不能以一次小修和编译通过宣称解决。离屏 2.0/4.0 数值保持检查仍然有效，但不覆盖上述挂载行为。

## 本轮基础检查

- Xcode Debug arm64 构建通过（9.24 秒），包含更新后的原生滤镜；仅有既有 AppIntents 元数据跳过警告。日志：`benchmarks/results/agent-review-build-20261017.log`。
- EDR 原型独立 `-Wall -Wextra -Werror` 编译通过；没有实际运行窗口或验证 HDR 色彩。
- 延迟窗口与预取小检查通过：24/30/60fps、倍速、4K 和未知帧率。初版测试恰好落在浮点阈值 25ms 边界导致断言失败，改用远离边界的 24ms 数据后通过。
- 生产 FFmpeg 封面提取器的 MP3/FLAC、无封面及取消检查通过。
- `git diff --check` 通过；未做完整测试、GUI、长片或性能 benchmark。

没有找到足以复核交接中 2.49×/3.62× 的新微基准记录，因此不将其作为本轮验证结果。缓存同步快照实际使用 NSLock，不能称为“无锁”；内存命中省去异步解码，不等于实测 0ms 或保证永不闪烁。

## 下一步建议

1. 优先完善 EDR 呈现状态机：生产和呈现推进分离，保证暂停末帧可完成；色彩配置、ICC 清除、图层显隐和失败回退必须成套切换，再开放开关。
2. 封面缓存增加同路径在途任务合并、文件修改时间失效和内存压力清理；混合队列/迷你模式的实际效果交给用户确认。
3. 预取增加最小样本数与迟滞，按短期有效 PTS 处理 VFR；之后再用同源素材对比 P95 和峰值内存，决定是否继续收紧缓存。
