# 播放列表读取与缓存优化

## 本轮改动

- 仅选中“创建时间”排序时才扫描日期；扫描完成前保持原顺序，避免先按未知日期重排一次。切换排序、队列成员变化或关闭时，取消会传递给后台扫描，并在逐文件读取间检查取消。
- 同文件夹自动加入播放列表的扫描也接收取消信号，在逐文件筛选时停止。正在执行的单次系统目录/属性读取不能强行中断。
- 元数据按文件路径复用简洁/详细模式结果；切换到详细模式时复用已读取的时长。并发读取合并，基本信息请求可共享详细读取，详细请求可等待已有基本读取完成再升级。
- 在读取缓存和异步结果完成时检查媒体文件修改时间及大小，避免同路径替换后继续使用旧时长/封面。删除文件后不返回旧结果。没有增加持续文件监视，已显示的行在下一次读取时刷新。
- 完整缓存仍为最多 128 项；压缩封面另设 16MiB 总上限。列表封面缩小到不超过 192×108 后编码，音频封面不再以主画面的较大分辨率复制到列表缓存。
- 缺失/部分元数据结果保留 60 秒退避，下一次读取允许重试，避免仅因文件大小读取成功就永久缓存时长/封面读取失败。
- 列表行在加载完成时创建一次 `NSImage`，不再每次 SwiftUI 重算时从 JPEG 创建图片对象；行切换文件时清空旧内容。

没有更改用户的排序偏好、当前播放项或删除行为。列表封面缓存的文件失效判断针对媒体本身；本轮没有为独立 cover.jpg 的变化增加列表主动刷新。
