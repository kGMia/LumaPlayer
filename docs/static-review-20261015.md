# 播放器静态检查与修复 · 2026-10-15

本轮检查当前 SwiftUI 播放器、队列操作、预览任务、窗口转换及原生增强适配层。工作区没有 Git 基线，因此这是对当前源码的检查，不是完整历史 diff 审计。遵照用户要求，仅做编译检查；没有运行播放器、Computer Use、画质对比、性能测试或完整测试集。

## 已修复

### 异步预览可能跨文件污染缓存

`PlaybackChrome.swift / TimelinePreviewGenerator` 在 `await generator.image` 时允许 actor 重入。旧文件的任务完成时，原代码会直接写入当前文件的缓存。快速拖动还会累积多个解码请求。

- 按文件和请求代际检查完成结果，拒绝旧结果。
- 相同时间桶复用正在进行的任务；新请求取消旧图像生成，避免无界排队。
- 请求失败或预览关闭时清空显示图像，防止沿用上一时间点的预览。
- 亮度采样使用独立生成器，最大 64×36、缓存 8 张；交互预览保留 320×180、缓存 96 张上限。两类请求不会互相取消。
- 离开 adaptive 主题后忽略未完成的亮度采样结果。
- 拖动期间视频失效时仍结束 scrubbing 状态，避免控件一直停留在拖动状态。

这只减少无用请求和降低采样图像尺寸，不代表已测得解码耗时或功耗下降。AVFoundation 仍是额外的解码路径。

### 删除无关队列项会取消预热后的恢复播放

`MPVSession.m / mutatePlaylistID` 原先对所有删除操作清除 `_resumeAfterWarm`。若模型正在预热，删除非当前条目后可能一直暂停。现在仅切换播放条目或删除当前条目时清除该标志。

### 移至废纸篓失败时丢失队列和历史记录

`PlayerActions.swift / deleteQueueFile` 现在先完成文件移至废纸篓，再修改队列、最近播放和续播位置；失败则保留原状态并报告错误。非绝对本地路径不执行文件操作。本轮没有实际删除媒体文件。

### 共享硬解帧的色度与颜色标签不一致

`iive_surface.c` 原先在取得 VideoToolbox 帧时直接写入 centered chroma 附件，未对原来的左置/未知色度位置做重采样，还会修改解码器共享缓冲区的附件。

- 共享路径现在要求 BT.709 / BT.1886、有限范围、居中色度，并核对硬解缓冲区现有附件；不再修改借用的解码帧。
- 不满足共享条件的输入进入现有 swscale 转换路径。可能增加复制成本，这是保留正确像素语义的必要回退，不是零拷贝优化结果。
- `iive_surface_wrap` 仅用于已经规范化的模型输出/输入池，明确标记实际 BT.709 矩阵、有限范围、居中色度。
- RIFE 旁路/尾帧保留原始帧及其格式和色度信息，不再把任意原始硬解帧交给规范化输出包装器。
- Apple 插帧及 RIFE 在相关颜色/色度参数变化时重置相邻帧状态，避免跨格式推理。

### 原生超分 / Apple 插帧的宽色域支持超出当前转换契约

原适配器放行 P3、BT.2020、其他 gamma 等输入，但复制路径固定生成 BT.709 附件，包装输出又继承原矩阵。当前实现不足以证明这些情况下标签和像素一致。

本轮将 **FSRCNNX Metal、Apple SR、Apple FI** 限制回明确的 **BT.709 primaries / BT.1886 SDR**；其他输入不加这些滤镜，UI 显示颜色限制旁路原因。符合条件的视频仍可因格式、尺寸等其他限制旁路。GLSL 与 RIFE 原有其他 SDR 路径不在此次收紧范围内，也未因此获得新的画质验证。HDR 继续旁路增强。

## 下一步优先级

1. **统一颜色输入契约，再优化拷贝。** 将范围、矩阵、色度位置显式纳入 Metal 输入转换；优先直接支持常见 left chroma NV12，避免本轮正确性回退带来的 CPU 转换。按后端分别扩展 P3 / gamma 支持，不能只扩大格式白名单。需要颜色样本验证后再启用。
2. **隔离播放控制与耗时任务。** 将预热、用户暂停、文件切换做成显式状态机；为后台文件/元数据任务增加取消与超时策略。队列封面当前仍使用串行任务链，一个慢资源会拖延后续项目。
3. **减少重复解码。** 自适应玻璃最终从实际播放帧低频读取亮度统计；时间轴预览保留独立异步服务。这样可进一步避免 AVFoundation 和 mpv 同时解码当前文件，且两者格式支持不一致时仍有明确降级。
4. **按实际瓶颈优化 RIFE / SR。** 给输入转换、推理、输出等待和呈现分别增加低开销计时，再决定是否融合 GPU 操作或调整推理分辨率。不要仅凭使用 MPSGraph 推断 Neural Accelerator 使用率；暂不引入更重的模型作为默认。
5. **收敛工程与交付。** 拆分 `PlayerModel` 的队列、增强计划和持久化职责；接入版本控制以便比较与回退；将原生库及依赖打入应用并验证签名后，再作为脱离开发工作区的应用发布。
