# RIFE Lite experimental path — 2026-10-24

- Fixed a correctness issue in both stateless and streaming Metal inference: official v4.26 / v4.25 Lite overwrite each stage mask (`mask = m0`); only flow accumulates. The previous backend added masks. The fused kernel now copies the new mask, the MPSGraph fallback uses a GPU copy, and the redundant mask-add graph/probe is omitted. Playback still uses v4.26; no preference/model switch is made.
- Official Lite uses channels `[192,128,96,64,24]`, scales `[32,16,8,4,1]` and 128-pixel internal alignment. Its model-dependent padding is now respected at all three public inference entry points. `fast` still means quarter-resolution inference, not the Lite architecture. The official wrapper's scale list is used; the IFNet function's default list is stale.
- Added strict inference tensor schemas, checked tensor byte ranges, safe `weights_only=True` conversion, source/archive/output hashes, and model selection retained across tier preparation. Lite is CLI-only until real-footage quality/performance comparison; it is not bundled in the app or displayed as a supported playback option.

Prepare with a Python environment containing PyTorch and NumPy:

```sh
python scripts/prepare-rife-lite.py
bash scripts/build-native.sh
python3 benchmarks/compare_rife_models.py --width 1920 --height 1080 --tier fast --target-fps 48 --pairs 20 --output /tmp/iive-rife-models.json
```

`--archive .research/rife-v4.25-lite-download` reuses the downloaded, checksum-pinned archive. Compare again with `--reverse` and a new output filename to expose ordering/thermal bias. The report includes model SHA-256, padding, format, real 24/30→48/60 timesteps, GPU span and CPU wait. It is synthetic inference throughput, not decoder/player/display FPS or a quality score. GPU span and CPU wait overlap.

For an explicitly tagged SDR BT.709 clip, offline visual comparison is available without changing player settings:

```sh
native/RIFEBackend/.build/release/iive-rife process INPUT.mov NEW-OUTPUT.mov 48 fast --no-fallback --model build/models/rife-v4.25-lite.rmw
```

Outputs must not already exist. This path remains AVFoundation-based and does not imply MKV/WebDAV input support in the CLI. The player retains its existing mpv compatibility.

Validation: native builds; three selected architecture/mask-kernel checks; 128×128 HQ and fast, 24→60 NV12 smoke runs for both models (two measured source pairs each). The official 4.26 archive's 158 inference tensors match bundled weights byte-for-byte after FP16 conversion. No full regression, real-footage numerical parity study, 1080p benchmark or GUI playback validation. Small smoke timings are not a speedup claim. Build/signature logs and smoke JSON are under `benchmarks/results/rife-lite-*20261024.*`.

Sources: [official model list and weight license](https://github.com/hzwer/Practical-RIFE#trained-model), [official Lite archive](https://drive.google.com/file/d/1zlKblGuKNatulJNFf5jdB-emp9AqGK05/view), [official 4.26 archive](https://drive.google.com/file/d/1gViYvvQrtETBgU1w8axZSsr7YUuw31uy/view). Both archives' IFNet and inference wrappers were read; their Python code was not executed. SHA-256 records: `build/models/rife-v4.25-lite.json` and `benchmarks/results/rife-v426-source-audit-20261024.json`.

## Short real-footage follow-up

Added a bounded-memory evaluation CLI and paired runner:

```sh
python3 benchmarks/compare_rife_video.py INPUT.mov --pairs 8 --start 0 --tier fast --target-fps 48 --output /tmp/iive-video-comparison
```

Use a new output directory; repeat with `--reverse` to expose order bias. Input must be a local AVFoundation-readable, unrotated, explicitly tagged SDR BT.709 video below the target FPS. Unknown color/HDR is rejected. The runner records input/model hashes and verifies matching source timestamps and output counts. It never changes player settings.

Quality holds out every other decoded frame, predicts it from its neighbors using actual PTS, and reports pooled RGB PSNR/MAE alongside nearest-frame and temporal-blend baselines. For a 24fps source this measures **12→24 reconstruction**, not 24→48 quality. A separate pass measures adjacent-frame 24→48/60 inference, excluding CPU quality scoring. BGRA/AVFoundation measurements are not the player's NV12/mpv, audio, display or SR pipeline. GPU span overlaps CPU wait; decode-call duration is not end-to-end decoder cost.

Basic M5 run: the existing Tears of Steel source is **1920×800, 24fps**, despite its `1080p` filename. A new 1.5s copy starting at 60s was explicitly tagged with a **BT.709 SDR assumption**, not verified source color metadata. Original media was unchanged. Exact preparation and file hashes are in [fixture provenance](../benchmarks/results/rife-real-fixture-20261024.json).

- Eight held-out frames: 4.26 PSNR **38.92dB**, Lite **38.05dB**; nearest-frame **26.86dB**, blend **32.27dB**. These are code-value errors, not a perceptual/ghosting assessment; this single interval does not establish motion/occlusion/cut coverage.
- Eight adjacent-frame pairs, fast 24→48, after warmup: mean model-call time 4.26 **9.08ms** / Lite **8.22ms**. Reversing order gave 4.26 **8.68ms** / Lite **8.78ms**. The apparent advantage did not persist; **no stable Lite speedup established**.
- [Forward report](../benchmarks/results/rife-real-short-tagged-20261024/report.json), [reverse report](../benchmarks/results/rife-real-short-reverse-20261024/report.json). Both input hashes remained unchanged and paired comparisons passed. The first untagged fixture was correctly rejected; retained separately as `rife-real-short-20261024`.
- Native Release build and RGB metric smoke checks passed. No GUI, full regression, sustained load or native-player performance test. No app repack was needed for these CLI-only additions.

Keep Lite experimental and retain 4.26 in the player. Next: prototype SPAN SR separately, measure matched-resolution quality/GPU cost against FSRCNNX, and only integrate if useful. Wider RIFE motion/cut samples and user visual review are needed before exposing a Lite selector.
